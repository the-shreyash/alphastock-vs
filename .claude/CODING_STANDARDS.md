# StockAssist AI
## Coding Standards

Version: 1.0

Status: Active Development

---

# Purpose

This document defines the coding standards for StockAssist AI.

Every line of code generated by developers, AI assistants, or automation must follow these standards.

The goals are:

- Readability
- Maintainability
- Scalability
- Consistency
- Performance
- Security

Code should always be written for humans first and computers second.

---

# Engineering Principles

Always write production-ready code.

Never write quick hacks.

Prefer clarity over cleverness.

Write self-documenting code.

Optimize only after measuring.

Every feature should be testable.

Every function should have a single responsibility.

# Component Rules

One component

One responsibility.

Avoid components larger than 300 lines.

Split into child components when necessary.

Reusable components belong in

components/ui

Feature-specific components belong inside feature folders.

---

# React Rules

Use Functional Components only.

Never use class components.

Prefer Hooks.

Use React Query for server state.

Use Context only for global state.

Avoid unnecessary prop drilling.

---

# State Management

# Error Handling

Never ignore errors.

Use centralized error handling.

Return meaningful messages.

Log internal errors.

Do not expose implementation details.

# Accessibility

Use semantic HTML.

Add ARIA labels.

Support keyboard navigation.

Maintain WCAG AA compliance.

Provide visible focus states.

---

# Performance

Lazy load routes.

Code split large pages.

Memoize expensive computations.

Optimize images.

Avoid unnecessary re-renders.

Virtualize long lists.

---

# Security

Never expose secrets.

Validate all inputs.

Escape outputs.

Sanitize HTML.

Use HTTPS.

Use secure cookies where applicable.

Verify permissions on every protected endpoint.

---

# AI Development Rules

Never hardcode AI responses.

Always separate

Prompt

Context

Response

Track

Model

Latency

Tokens

Cost

Store AI interactions for analytics where appropriate.

---

# Broker Rules

Never hardcode broker logic.

Use Broker Adapter pattern.

All brokers implement the same interface.

Never expose broker tokens.

---

# Event Rules

Publish events for major actions.

Examples

trade.created

portfolio.updated

subscription.upgraded

notification.sent

Events should be immutable.

# Git Commit Convention

fix(broker): resolve token refresh issue

refactor(ai): simplify context builder

docs(api): update endpoint reference

test(portfolio): add holdings service tests

chore(deps): upgrade dependencies
