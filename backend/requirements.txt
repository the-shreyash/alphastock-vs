# ==============================================================================
# StockAssist AI — Backend PRODUCTION runtime dependencies
#
# WHY THIS FILE LOOKS DIFFERENT NOW (PH2.8)
# -----------------------------------------
# Until PH2.8 this file was a raw `pip freeze` — 118 fully-pinned packages, no
# structure, no record of which ones the application actually imports. That is
# how a dependency set rots: a package added for a feature that was later cut
# stays forever, because nobody can tell a live dependency from a fossil without
# reading every import in the codebase. PH2.1 measured the cost — ~220 MB of the
# runtime image was packages NO application module imports (litellm, boto3,
# botocore, stripe, s5cmd, the old google-generativeai SDK + grpcio/protobuf,
# pandas, numpy, openai, huggingface, tiktoken, …). PH2.8 removed them.
#
# HOW THIS SET WAS DERIVED (and how to re-derive it)
# --------------------------------------------------
#   1. Enumerate every third-party module the application imports — including
#      lazy imports inside functions and try/except blocks.
#   2. Map those to their distributions; that is the DIRECT set below.
#   3. Compute the dependency CLOSURE of the direct set from installed metadata
#      (importlib.metadata.requires, evaluating environment markers, excluding
#      `extra ==` optional deps). Everything in the closure and nothing else is
#      the TRANSITIVE set below.
#   4. Prove it: the closure is closed under its own core requirements (pip
#      installs exactly this set, nothing missing), and with every REMOVED
#      module blocked at import, the entire runtime module graph still imports.
#   See docs/infrastructure/CONFIGURATION.md §"Dependency Management" for the
#   full method, the removal ledger, and how to add a dependency correctly.
#
# RULES FOR EDITING
# -----------------
#   * A new DIRECT dependency goes in the direct section WITH a comment naming
#     the module that imports it. No orphan pins.
#   * Never `pip freeze > requirements.txt` again — it re-buries the structure
#     and re-imports the fossils. Add the one package you need and let its
#     transitives land in the transitive section, pinned.
#   * Dev/CI tooling (pytest, black, flake8, isort, mypy, watchfiles) belongs in
#     requirements-dev.txt and MUST NEVER appear here — the runtime image is
#     built from this file alone (backend/Dockerfile), and every package here is
#     production attack surface.
#   * Pins are exact (==) for reproducible builds. Bumps flow through the
#     dependency-update policy in .claude/SECRETS.md.
# ==============================================================================
