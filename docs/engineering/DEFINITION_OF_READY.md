# Definition of Ready (DoR)

## Purpose
To ensure that an issue or ticket has enough detail and context before engineering work begins.

## Rules
- An issue must not be pulled into a sprint unless it meets the DoR.
- Product or engineering leads must provide the necessary details before assignment.

## Responsibilities
- **Product Manager / Requester:** Provide clear requirements and acceptance criteria.
- **Engineering Lead / Assignee:** Review the ticket and confirm it meets the DoR.

## Checklist
- [ ] The problem or feature is clearly defined.
- [ ] Acceptance criteria are explicitly listed.
- [ ] Dependencies (design assets, API specs, third-party credentials) are available.
- [ ] Technical approach has been discussed and agreed upon (if complex).
- [ ] An estimation or t-shirt size has been provided.

## Approval Workflow
1. Ticket is drafted.
2. Team reviews the ticket during planning or grooming.
3. If checklist is met, the ticket is marked "Ready for Development".
